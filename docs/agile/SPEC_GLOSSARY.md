## Group 1

- Tables `users`, `incidents`, `incident_history`: canonical PostgreSQL tables from migration 0001; incidents fields `id`, `owner_id` (FK users, ON DELETE RESTRICT), `title` (5–100), `description` (10–1000), `category`, `priority`, `status`, `created_at`, `updated_at` — defined in `openspec/changes/backend-foundation-workspace-layered-fastapi-skeleton-5f2dfa7c/backend.yaml`, section "entities".
- History entry fields: a history row carries exactly `id` (UUID), `incident_id` (UUID FK), `previous_status` (nullable; NULL = initial creation entry), `new_status`, `changed_by` (UUID FK users), `changed_at` (TIMESTAMPTZ) — never `from_status`/`to_status`; this naming is binding for API payloads and client DTOs — defined in `openspec/changes/backend-foundation-workspace-layered-fastapi-skeleton-5f2dfa7c/backend.yaml`, section "entities: incident_history".
- `GET /health`: public liveness probe returning 200 `{"status": "ok"}`, no auth, no rate limit, does not ping the DB — defined in `openspec/changes/backend-foundation-workspace-layered-fastapi-skeleton-5f2dfa7c/specs/main/spec.md`.
- `POST /api/auth/login`: body `{email, password}` (EmailStr + non-blank password); 200 `{"access_token", "token_type": "bearer", "expires_in_seconds": 28800}`; 401 `{"detail": "Credenciales inválidas"}` uniform for wrong password AND nonexistent email; 422 FastAPI structured shape; 429 `{"detail": "Demasiados intentos. Inténtelo de nuevo más tarde."}` + `Retry-After` — defined in `openspec/changes/sign-in-session-jwt-and-profile-api-with-rate-limited-387ee2a1/backend.yaml`, section "endpoints: post-auth-login".
- `GET /api/me`: bearer-authenticated profile returning `{id, email, role, active, created_at}`; 401 `No autenticado` for bad tokens, 403 `Cuenta inactiva` for a deactivated subject; `password_hash` never in any response — defined in `openspec/changes/sign-in-session-jwt-and-profile-api-with-rate-limited-387ee2a1/backend.yaml`, section "endpoints: get-me".
- Session JWT: HS256 pinned (`algorithms=["HS256"]` allow-list on decode), claims `sub` (user UUID string)/`role`/`exp`, TTL 28800 s (constant `TOKEN_TTL_SECONDS`), no refresh; bcrypt used directly (no passlib) — defined in `openspec/changes/sign-in-session-jwt-and-profile-api-with-rate-limited-387ee2a1/design.md`, section "2. Security core".
- Login rate limiting: two independent in-process in-memory failure counters (per client IP, per submitted email), sliding window, env-configurable via `LOGIN_RATELIMIT_IP_MAX` / `LOGIN_RATELIMIT_EMAIL_MAX` / `LOGIN_RATELIMIT_WINDOW_SECONDS` (defaults 5 / 5 / 900 s), failures only (success consumes nothing), uniform regardless of account existence — defined in `openspec/changes/sign-in-session-jwt-and-profile-api-with-rate-limited-387ee2a1/design.md`, section "3. Rate limiter".
- `GET /api/incidents`: owner-scoped plain JSON array (no pagination envelope), `created_at` DESC; optional `?status=pending|in_progress|resolved|all` (unknown value → 422 loc `["query","status"]`); list items carry exactly `{id, title, category, priority, status, created_at, updated_at}` and omit `description`; no 403/404 cases — defined in `openspec/changes/incident-rest-api-owner-scoped-list-status-filter-create-as-b3b13c6f/specs/main/spec.md`, sections "Owner-scoped incident list" and "Compact list item schema".
- `POST /api/incidents`: body exactly `{title, description, category, priority}` with `extra="forbid"`; responds 201 with the flat created incident (`status` always `"pending"`, `created_at == updated_at`, owner = token subject) and inserts exactly one initial history row (`previous_status` NULL) in the same transaction — defined in `openspec/changes/incident-rest-api-owner-scoped-list-status-filter-create-as-b3b13c6f/specs/main/spec.md`, section "Create-as-Pending incident".
- `GET /api/incidents/{id}`: 200 = flat full incident (`{id, title, description, category, priority, status, created_at, updated_at}`) plus `history` array ASC by `changed_at`; non-UUID path id → 422; missing AND foreign id → the same 404 `{"detail": "Incidencia no encontrada"}` — defined in `openspec/changes/incident-rest-api-owner-scoped-list-status-filter-create-as-b3b13c6f/specs/main/spec.md`, section "Owner-only incident detail with chronological history".
- `PATCH /api/incidents/{id}/status`: support-only via `require_role("support")` checked before any lookup; body's only field is `new_status` (`extra="forbid"`); 200 `{"incident", "latest_history"}`; linear matrix pending→in_progress→resolved with resolved terminal; 403 `No autorizado` (employee, uniform even for bad ids), 404 `Incidencia no encontrada` (support, safe), 409 `Transición de estado no válida`, 422 structured — defined in `openspec/changes/support-only-status-transition-api-with-linear-matrix-and-d2af657f/specs/main/spec.md`.
- Error-body contract: all error bodies are `{"detail": "<mensaje>"}` with exact Spanish strings (401 login `Credenciales inválidas`, 401 protected `No autenticado`, 403 inactive `Cuenta inactiva`, 403 role `No autorizado`, 404 `Incidencia no encontrada`, 409 `Transición de estado no válida`, 429 `Demasiados intentos. Inténtelo de nuevo más tarde.`, 500 `Error interno del servidor`); 422 keeps FastAPI's default structured shape; the Android client copies `detail` verbatim — defined in `openspec/group-decisions.md`, section "API contracts".
- Wire value vocabularies: statuses `pending|in_progress|resolved` (Spanish labels Pendiente/En progreso/Resuelta UI-only), categories `systems|equipment|access|other` (Sistemas/Equipos/Acceso/Otro), priorities `low|medium|high` (Baja/Media/Alta), roles `employee|support`; JSON fields `snake_case`, dates ISO 8601 UTC with Z suffix, IDs opaque UUID strings — defined in `openspec/group-decisions.md`, section "Canonical names".
- Immutable append-only history: application code never updates or deletes `incident_history`; repositories expose only append + read-only queries; every accepted transition atomically updates `incidents.status`/`updated_at` and appends exactly one row — defined in `openspec/changes/support-only-status-transition-api-with-linear-matrix-and-d2af657f/specs/main/spec.md`, section "Atomic transition with immutable history".
- Canonical Kotlin names (mobile): enums `IncidentStatus`/`IncidentCategory`/`IncidentPriority`/`UserRole` in `data/model/Enums.kt`; domain models `Incident`, `IncidentHistoryEntry`, `UserProfile`; seam `IncidentRepository` (interface) with `FakeIncidentRepository` (US-005) and `RetrofitIncidentRepository` (US-012); `FakeAuthService`; `TokenStore` interface with in-memory fake (US-005) and Keystore-backed impl (US-012); `IncidentDto` etc. live only at the DTO layer — defined in `openspec/group-decisions.md`, sections "Canonical names" and "Shared components", and `openspec/changes/android-mock-first-foundation-gradlecompose-project-9623d283/design.md`.
